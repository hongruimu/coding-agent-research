# 进度与证据边界

> 本文记录每个已完成阶段的「做了什么、证据是什么、边界在哪」。阶段按能力领域推进；编号只是内部里程碑，读者不需要记。

## 阶段一：评测基线（已完成）

**解决了什么**：在还没有任何 Agent 运行时之前，先回答「一个任务怎样算完成、怎样独立判定」。

**做了什么**：

- 定义三类最小评测任务：仓库探索、小型 Bug 修复、安全边界；
- 每类任务配独立 grader（验收器），把 Agent 的「候选产物」和「隐藏判据」分离；
- 建立运行记录（run-record）、预算语义，以及敏感信息脱敏与截断。

**核心判断**：被评测对象（Agent 自述、自己生成的日志、自己改过的测试）不能当裁判；判定必须来自独立证据，且证据只能证明它实际观测到的那些事。

**证据**：`tests/` 中的合同、grader 与安全边界测试；`evals/` 中的任务夹具与 grader。

**边界**：只证明「判定逻辑正确」，尚未接入真实执行闭环；OS/容器/网络隔离、真实 Token 成本等尚未验证。

## 阶段二：核心协议与模型接口（已完成）

**解决了什么**：Agent 与模型之间需要一门最小的「语言」——消息、模型回答、工具调用、工具结果长什么样、彼此如何关联。

**做了什么**：

- `coding_agent.protocol`：四个冻结数据类、显式的 `final` / `tool_calls` 互斥分支、全历史唯一的工具调用 ID 回挂；
- `coding_agent.model`：同步 `Model` 接口 + FIFO 的 `ScriptedModel`（假模型）。

**核心判断**：

- 先定「结构」（语言），再定「动作」（何时调、何时停），两者不混；
- 状态显式化，不靠「字段是否为空」推断；
- 协议正确性用确定性假模型证明，真实模型只做独立适配验证；
- 错误分层：协议错误 / 模型错误 / 工具错误走不同路径。

**证据**：聚焦测试与全量回归（`123 passed`），含大量「构造失败」用例（错 ID、重复 ID、非法分支、脚本耗尽等）。

**边界**：这只是进程内内存协议 + 测试替身；真实循环、工具执行、真实模型、异步、预算、持久化都还没有。

## 阶段三：工具调用协议（已完成）

**解决了什么**：模型输出的是「请求」（调哪个工具、传什么参数），真正执行是另一层；两者之间需要一份明确约定——坏请求当场拒绝、执行失败转成结果、结果精确回挂。

**做了什么**：

- `coding_agent.tools`：工具以唯一名称注册到执行函数；从执行函数签名推导参数 Schema（必填 / 可选 + 类型）；
- 按 Schema 校验参数；执行并捕获异常转 `is_error=True`；结果复用 `ToolCall.id` 回挂，能通过历史校验。

**核心判断**：

- 请求和执行分层：模型只「决定」做什么，执行器「做」；
- 坏请求（工具不存在 / 参数非法）当场拒绝，执行失败转结果数据，两者不能混；
- Schema 从签名推导，单一来源，避免「声明」和「代码」漂移。

**证据**：注册 / 校验 / 执行 / 回挂的单元与集成测试；全量回归 `167 passed`。

**边界**：纯内存确定性工具；真实文件读写 / Shell、循环、预算 / 超时 / 权限、异步都还没有；「签名声明层」正确性（函数签名即用户声明）不在此验收范围。

## 阶段四：确定性执行循环（已完成）

**解决了什么**：模型、工具、结果都有了，但还缺一条「何时问模型、何时停」的控制流；循环的停止不止「做完」一种，还有「预算用尽」和「出错」。

**做了什么**：

- `coding_agent.loop`：纯函数 `run`，把「模型回答 → 执行工具 → 结果回注 → 再问模型」串成确定性多轮循环；
- 停止分三层：`final` 正常完成；预算用尽抛 `StepLimitExceededError`；协议错误 / 模型异常原样抛出；
- 工具执行失败（`is_error=True`）不停止，而是作为结果喂回模型继续；
- `coding_agent.adapters`：把真实模型（OpenAI Responses 格式）原始输出适配成协议里的 `ModelResponse`，独立于循环正确性验证。

**核心判断**：

- 停止只由「最终回答 / 预算 / 异常」三选一驱动，循环不吞异常、不重试、不猜测；
- 「机制」和「结果语义」分离：预算用尽抛异常，而不是返回一个披着「最终回答」外衣的「没做完」；
- 坏请求（工具不存在 / 参数非法）当场停，执行失败喂回模型继续；
- 确定性 = 同一输入两次运行逐字段相等，不是「看起来一样」。

**证据**：多轮 / 停止 / 预算 / 错误传播 / 确定性的单元与集成测试；全量回归 `195 passed`。

**边界**：纯内存同步循环，无真实文件读写 / 命令执行、无重试 / 超时 / Token 成本 / 权限、无异步 / 并发；真实模型适配只验证固定样本映射，不接真实供应商、不证端到端成功率。

## 下一步

按真实阻塞问题推进，下一件最小的事是：**安全仓库探索**（在明确工作目录内列出、读取、搜索代码，不越过允许范围），这是「让 Agent 真正读写代码」的第一步，需要先建立最小安全边界。在形成「能读写代码、能跑验证」的最小闭环之前，不提前引入上下文预算、安全审批、多 Agent 等复杂能力。
